Concept
How the engine works, and what the research says



  

    
The generator is procedural art, not a template

    
Every patch is a deterministic function of hash(text) ⊕ seed. Change the seed and you get a sibling; keep it and you get the same song back. The layers, in order:

    
1 · Form detection

    
Tags already in the source ([Verse 1], [Chorus], [Bridge]…) are stripped before anything else. A tag line becomes a role hint for the stanza under it, so a chorus you marked stays a chorus; intro, outro and instrumental tags are dropped and regenerated. Brackets inside a lyric line are removed. Stanzas are split on blank lines. A stanza that repeats (fuzzy match on normalized words) becomes the [Chorus]. A short stanza directly before a chorus becomes [Pre-Chorus]. A late, unrepeated stanza with a different vocabulary becomes [Bridge]. Single-stanza poems are folded into verse / chorus by repeating the strongest couplet.

    
2 · Energy curve from value noise

    
A 1-D value-noise field (smoothstep interpolation between seeded lattice points) is blended with an archetype curve (rise, wave, collapse, plateau). Each section samples the field once. That number drives everything downstream: which mood word, how many instruments enter, whether the vocal is whispered or belted, whether the peak line is capitalized.

    
3 · Palette with weighted drift

    
Each genre family is a palette (instruments, grooves, mix words, adlibs, exclusions). The mutation slider is a temperature: at 0 the engine only draws from the family; higher values let it borrow one or two elements from a neighboring family, which is exactly how the field guide suggests escaping the "pop gravity well".

    
4 · Grammar for the Style box

    
A sentence grammar fills the community's master template: identity, vocal, core instruments, rhythm, arrangement arc, dynamics, atmosphere, mix, master. Sentences end with periods, not commas, because Suno parses a period as a hard boundary and a comma as "optional".

    
5 · Lyric-level typography

    
Rules from the "dirty tricks" series, applied by energy: ALL CAPS only on the single highest-energy line (contrast is the whole point), (parentheses) echoes on chorus tails, inline [adlibs] only in families that use them, syllable stretching lo-o-ove on a ballad's peak word, *asterisk* cues for atmosphere.

  

  

    
Suno v6 syntax, condensed

    
Current as of the September 2026 v6 launch. Three models: v6 (control), v6-wild (discovery), v6-mini (fast, free tier). All three generate up to 8 minutes.

    
Two fields, two jobs

    
    
      
  • Style box: how it sounds. Nothing here is sung. Comma or period separated prose, no brackets. Order by influence: genre → mood → lead instrument → vocal → production. 3–5 tags for simple songs, up to ~15 for control, beyond ~20 the model gets confused.
    • 
      
  • Lyrics box: what is sung, plus [bracket tags] that shape the arrangement. Tags are case-insensitive and probabilistic cues, not commands.
    • 
      
  • Exclude styles (Advanced options): first-class negative field. More reliable than inline no drums; combine both for stubborn elements.
    • 
    

    
Section tags that are validated

    
[Intro] [Verse] [Verse 2] [Pre-Chorus] [Chorus] [Post-Chorus] [Hook]
[Bridge] [Break] [Breakdown] [Build] [Drop] [Interlude]
[Instrumental] [Solo] [Outro] [End] [Fade Out]

    
Pipe stacking (the v5.5/v6 pattern)

    
[Section | Mood | Vocal | Instruments | Movement | Space | Production]
[Chorus | explosive | full voice | wide synths | stacked harmonies | vocal forward]

    
Max ~7 elements, most important first, never contradictory pairs in one tag. Stacked tags override the Style box for that section.

    
Typography the vocal model reads

    
LINE IN CAPS!        louder, shouted (use once, for contrast)
line in lowercase     delicate
(echo these words)    backing vocal / call-and-response
[yeah!] inside a line adlib, not a section
lo-o-o-ove            stretched note
i-hit-the-street      hyphen run = faster flow
word, word.  word...  breath · hard reset · drag
*rain falling*        non-sung atmosphere
reed / lyve / bahss   phonetic respelling for homographs
[End]                 terminal tag, ~85–90 % effective

    
Sliders

    
    
      
  • Weirdness 0–100 %, 50 is "expected". Covers 10–30, experimental 70+.
    • 
      
  • Style influence: vague tags want 70–90, very specific tags 40–60.
    • 
      
  • Variety (v6): can rewrite your style tags; set 0 when you need them preserved.
    • 
      
  • Change one slider per test. Max Mode helps acoustic/orchestral, does little for electronic.
    • 
    

    
Things that don't work well

    
    
      
  • Adjective soup (epic, beautiful, cinematic): describe audible behavior instead.
    • 
      
  • Prompt adherence decays after ~60 s: front-load the distinctive elements; build long songs with Extend or assemble sections in Studio.
    • 
      
  • Lyric bleed: short poetic lines in the style box get sung. Keep that box dense and technical.
    • 
      
  • DAW numbers (-14 LUFS, Q 1.4) do nothing in a prompt.
    • 
    

  

  

    
Build notes for the app

    
Everything on this page is one HTML file: vanilla JS, vanilla CSS, no build step, no dependencies. The engine is a pure function generate(text, knobs, seed) → patch, so the same code can run in a worker, a CLI, or a browser extension that fills Suno's form.

    
Module map

    
    
      
  • rng: mulberry32 + FNV-1a string hash, value noise.
    • 
      
  • form: stanza split, repeat detection, role assignment, syllable estimator.
    • 
      
  • palettes: seven dark-pop families as data (instruments, grooves, textures, moods, mix, exclusions). Add your own without touching logic. Artist names are deliberately absent: Suno ignores or blocks them, so each family describes the sound those records are made of instead.
    • 
      
  • compose: energy curve → section tags → typography passes.
    • 
      
  • style: grammar for the Style box, budget-aware (trims from the end of the priority list).
    • 
      
  • ui: knobs, tabs, variation bank, copy, URL-free state.
    • 
    

    
Roadmap ideas

    
    
      
  • Lock layers independently (keep structure, reroll palette), i.e. partial reseeding per module.
    • 
      
  • L-system expansion for intros/outros (I → I B rewrites that add a build or a break).
    • 
      
  • Markov chain over the community cookbook to grow new palettes.
    • 
      
  • Rhyme-scheme and meter detection to pick between sung vs rapped delivery per section.
    • 
      
  • A/B log: store seed + patch + your 1–10 score, then bias the sampler toward what scored well (a tiny "My Taste").
